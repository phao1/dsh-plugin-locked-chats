# dsh 锁定聊天

**把私密聊天收起来，把恢复权留给自己。** Day 0 for dsh：四位 PIN、工作区继承保护、本地恢复文件。忘记 PIN 后可用已保存的恢复文件无损重设。

[产品介绍、截图与 Codex 对比](https://github.com/phao1/dsh-plugin-locked-chats#readme) · [npm 安装包](https://www.npmjs.com/package/dsh-plugin-locked-chats)

[English](README.md) · **简体中文**

为 DeepSeek Harness 提供四位 PIN 保险箱，将指定聊天和工作区从日常导航中隐藏。**0.1.2** 增加 rc.3 兼容声明，保留 rc.2 支持和 **0.1.1** 的窗口重连修复，无需修改 dsh 源码。

> 这是应用内界面隐私功能，不是底层聊天数据的加密或安全隔离边界。

## 环境与安装

兼容目标为 DeepSeek Harness **0.2.1-rc.2 或 0.2.1-rc.3**；其他版本未声明兼容。插件界面目前为中文，本文档提供中英文切换。按你使用的客户端选择安装方式。

本轮交付 GitHub Release 安装包；npm `0.1.2` 尚未发布。以下链接可直接安装。

### 桌面端

在桌面端侧栏打开 **插件 → 添加插件**，输入以下安装包链接，安装后点击 **立即启用**，再重启桌面端：

```text
https://github.com/phao1/dsh-plugin-locked-chats/releases/download/v0.1.2/dsh-plugin-locked-chats-0.1.2.tgz
```

也可以使用桌面端提供的命令安装：

1. 启动一次桌面端，在应用菜单的 **管理 dsh 命令… → 安装** 中注册命令。
2. **完全退出桌面端**（仅关闭窗口会保留后台进程），打开新终端执行：

   ```sh
   dsh plugin --profile desktop add https://github.com/phao1/dsh-plugin-locked-chats/releases/download/v0.1.2/dsh-plugin-locked-chats-0.1.2.tgz
   ```

3. 重新打开桌面端。

桌面端自带运行时。命令行安装请使用上述桌面端注册的 `dsh`；npm 全局安装的 `dsh` 不能管理桌面端 profile。参见 [官方桌面端说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.zh.md)。

### Web 端

需要 **Node.js 24+**，执行：

```sh
dsh plugin --profile web add https://github.com/phao1/dsh-plugin-locked-chats/releases/download/v0.1.2/dsh-plugin-locked-chats-0.1.2.tgz
```

重启对应 dsh profile，刷新 Web 页面。`web` 和 `desktop` 的插件安装独立，使用哪个客户端就安装到对应 profile。

不同独立安装应使用各自的插件数据目录。生产测试前请备份 dsh 数据及插件状态。

## 从 0.1.0 / 0.1.1 升级

完全退出桌面端后，使用桌面端注册的 `dsh` 执行上方 `--profile desktop add` 命令，再重新打开应用。Web 端执行上方 `--profile web add` 命令后重启对应 profile 并刷新页面。同样的命令也可将此前的本地修复包替换为正式发布版。

现有聊天、PIN 和恢复码会保留，无需重设凭据。详见 [0.1.2 版本说明](CHANGELOG.md)。

## 宿主兼容策略

声明范围为 `0.2.1-rc.2 || 0.2.1-rc.3`。RC 版本的插件接口仍可能变化，因此每个新宿主版本都需检查接口、安装包和用户行为后再扩展支持。不使用 `*`，也不静默豁免宿主兼容检查。范围之外的版本属于尚未验证，并不等于已证明运行不兼容。

`0.1.2` 已通过两套接口环境各 71 项自动化测试、构建和类型检查，并在官方 rc.2/rc.3 真实 Web 宿主安装后完成锁定、PIN 解锁、继续聊天、搜索过滤、原生视图/分组和拖拽持久化验收。测试回复来自本地合成模型。桌面端 rc.3 仍待用户验收，Web 验证不等同于桌面端验证。

## 已有能力

- 从原生会话菜单锁定单条聊天，或在保险箱中锁定整个工作区。
- 从普通历史、置顶和已适配的搜索结果隐藏受保护聊天。工作区锁同时保护其中已有、以后新建及派生的聊天。
- 按工作区查看锁定聊天与最近正文摘要，通过 dsh 原生对话界面继续聊天。
- 复用原生输入、附件、模型、权限、指令、菜单和弹窗，保留侧边栏视图、搜索、拖拽和排序。
- 锁定区与普通区统一滚动，工作区标题保持顶部固定。
- 输入完整四位 PIN 自动验证；创建或修改新 PIN 时支持查看输入，减少误输。
- 使用独立保存的恢复码无损恢复访问，不删除聊天。
- 在插件自有记忆工具中分离普通记忆与私密记忆。

## 使用保险箱

1. 打开聊天菜单，选择 **锁定聊天**。
2. 首次使用时设置并确认四位 PIN，保存恢复码并回填确认备份。
3. 点击工作区标题下的 **锁定聊天**，输入 PIN 后选择已有聊天或新建聊天。
4. 点击 **立即上锁** 结束本次访问。聊天仍保持锁定。

保险箱中的 **锁定工作区** 可以保护整个已有工作区。解除工作区锁不会移除单独设置的聊天锁，也不会移动文件、目录、工作区归属或置顶关系。

**0.1.1** 会在闲置或 Host 重启导致窗口连接失效后，通过再次输入 PIN 自动重新连接。未完成的凭据设置或恢复操作过期后会返回起点；已保存的 PIN、恢复码和聊天保持不变。

**解除锁定** 会恢复普通可见状态。若聊天受到工作区或父聊天的继承保护，需先解除对应来源；同时存在独立锁时还需解除独立锁。插件**不提供聊天删除、回收站或永久删除**。需要管理或删除聊天时，先解除锁定，再使用宿主实际支持的操作。

## PIN 与恢复码

在 **更多 → 设置 → 锁定聊天** 中修改 PIN、恢复访问或更换恢复码。

恢复码可在忘记 PIN 时无损重设。请将它与应用分开保存：它是访问凭据，不是聊天备份。插件默认不保存明文恢复码。如果 PIN 与恢复码都丢失，插件没有无凭据恢复入口。

默认连续错五次进入 60 秒冷却；此后每再错五次，冷却时间翻倍，最长 15 分钟；验证成功后清零。PIN 与恢复码分别限流，刷新或重启不会清除计数，输错不会删除聊天。

## 记忆行为

原生模型工具 `locked_chats_memory` 支持 `remember`、`search`、`forget`。请明确要求模型保存或忘记记忆；插件不会自动提取每条聊天。

| 会话状态 | 可读取 | 新增、修改与忘记 |
| --- | --- | --- |
| 普通会话 | 普通记忆 | 普通记忆 |
| 锁定会话 | 普通及私密记忆 | 私密记忆 |

权限来自真实会话、工作区和祖先锁状态，模型不能指定其他会话或记忆域。无法确认会话祖先状态时拒绝操作。

上锁不会清除之前形成的普通记忆；解除锁定不会将已有私密记忆迁入普通记忆。忘记记忆只处理插件库中的记忆条目，不会删除聊天。

## 保护范围与限制

- 界面隐藏不会加密日志、附件、文件或插件存储。
- 直接 API、CLI、文件工具、其他客户端、第三方搜索或引用，以及禁用或卸载插件，均可绕过界面保护。
- 记忆分离仅覆盖 `locked_chats_memory`，不控制第三方 MCP 记忆、文件、`AGENTS.md`、供应商记忆或其他跨会话引用。
- 旧分享不会被撤销，其他已打开窗口可能需要刷新。
- 插件不改变模型训练或数据留存设置。
- 文件访问保护、账户同步、移动端生物识别和完整后台任务资格限制尚未实现。
- 恢复码重设有意保留聊天，不复刻 ChatGPT 的重置删除行为。

工作区入口定位适配当前支持的宿主布局；无法识别时回退到浏览区域入口位置。原生侧边栏行及其事件仍由 dsh 管理。
